# Archiveo APP 设计方案（PRD + 技术/数据/交互）

> Archiveo｜知库：碎片输入 → AI 总结 → 归档成“文章”。本方案面向可直接开工的开发粒度，减少歧义。

---

## 1. 目标与范围

### 目标

用户把**网页链接 / 大段文字 / 图片**输入到 App，系统用大模型做分析与总结，在**保留源输入**的同时，自动**归纳分类**并整合成一篇“文章”，便于长期检索和导出。

### MVP 功能范围

1. 输入：链接 / 粘贴文本 / 图片（单张或多张）
2. AI 处理：摘要标题、关键词、结构大纲、思维导图（可视化/或结构数据）
3. 归档：每次输入生成 1 篇“文章”，可编辑标题/标签
4. 检索：关键词/全文/标签
5. 导入导出：本地文件导入、导出（JSON/Markdown/ZIP）

> 先不做：社交分享、多人协作、复杂权限、浏览器插件（可作为后续）。

---

## 2. 核心用户流程

### 流程 A：输入 → 生成文章

1. 用户点击「+ 新建」
2. 选择输入方式：
   - 粘贴文本（可多段）
   - 输入网页链接（支持多个链接）
   - 上传图片（可多张）
3. 点击「生成」
4. 显示生成进度（分步骤：提取 → 理解 → 组织 → 生成）
5. 生成完成进入文章详情页

### 流程 B：浏览/检索

- 首页列表：文章卡片（标题、关键词、时间、分类）
- 搜索：关键词/全文
- 筛选：标签/分类/时间

### 流程 C：导入导出

- 设置页：导入 / 导出
- 导出选择范围：全部 / 选中 / 时间段
- 导出格式：JSON（原始数据）/ Markdown（可读）/ ZIP（含图片附件）

---

## 3. 文章结构定义（核心数据模型）

每次输入生成一个 `Article`，包含：

- `summary_title`：AI 生成标题（用户可编辑）
- `keywords[]`：AI 生成关键词（用于检索与标签）
- `outline`：大纲（层级结构）
- `mindmap`：思维导图数据（建议用树结构 JSON，UI 再渲染）
- `sources[]`：源输入内容（必须保留）
  - 文本：原文分段
  - 链接：URL、抓取时间、页面标题、抽取正文、（可选）快照
  - 图片：文件引用、（可选）OCR 文本、图片描述（caption）

> “归纳分类整理”建议落在两层：
> - 文章内：大纲/思维导图组织
> - 文章间：自动分类 `category` + 标签 `keywords`

## 4. AI 能力设计

### 4.1 输入预处理（Ingestion）

- **链接**
  - 抓取网页 HTML → 正文抽取（Readability/Boilerpipe 类）
  - 提取：标题、作者、发布时间（可选）、正文、引用链接
- **文本**
  - 清洗：去多余空白、保留段落
- **图片**
  - 生成描述（image caption）
  - 可选 OCR：提取文字（中英文）

> 预处理输出统一为 `SourceChunk[]`：`{type, content, meta}`

### 4.2 LLM 任务拆分（推荐多步、可控）

1. **理解与主题提炼**
   - 产出：主主题、关键观点、受众/场景
2. **结构化组织**
   - 产出：大纲（层级）+ 每级要点
3. **摘要标题 + 关键词**
   - 标题：12~28 字符（英文可 5~10 词），可读性优先
   - 关键词：8~20 个（可包含同义词）
4. **思维导图数据**
   - 与大纲同源生成：树结构（root + children）
5. **分类建议**
   - 输出：`category`（单选/少量多选）、`tags`

### 4.3 输出格式（强制 JSON Schema）

为减少模型偏差，要求 LLM **严格输出 JSON** 并做校验/重试：

```json
{
  "summary_title": "…",
  "keywords": ["…","…"],
  "category": "…",
  "outline": [
    {"h": "一级标题", "points": ["要点1","要点2"], "children": [
      {"h":"二级标题","points":["…"],"children":[]}
    ]}
  ],
  "mindmap": {
    "text": "根节点",
    "children": [{"text": "…", "children": ["..."]}]
  }
}
```

### 4.4 长文本策略

- 分块（chunk）+ 逐块摘要（map）+ 汇总（reduce）
- 保留引用：在 outline/points 里可选加 `evidence_ids[]` 指向源段落，便于溯源高亮

## 5. UI / 交互设计

### 5.1 信息架构

底部 3~4 个主入口：
- 首页（文章列表）
- 新建（输入）
- 搜索
- 设置（导入导出、模型/隐私）

### 5.2 新建页（最关键）

- 顶部：输入方式 Tab（链接 / 文本 / 图片）
- 主区：输入框或上传区
- 下方：可选高级选项（折叠）
  - 语言识别/指定
  - 摘要长度：短 / 中 / 长
  - 是否 OCR（图片）
- 主按钮：`生成文章`

### 5.3 文章详情页（四块固定区）

1. **标题区**：标题 + 分类 + 时间（可编辑标题/分类）
2. **关键词区**：chips 标签（可增删）
3. **结构区**：
   - Tab1：大纲（可折叠）
   - Tab2：思维导图（简洁节点图）
4. **源内容区**（只读，默认折叠）：
   - 链接正文（可展开）
   - 粘贴文本（分段）
   - 图片（网格 + 点击查看）

> 原则：默认只展示“结论（标题/关键词/大纲）”，源内容折叠，避免信息噪音。

## 6. 数据与存储

### 6.1 本地优先（推荐）

- SQLite（或 Realm）存结构化数据
- 图片/快照放本地文件系统（路径存库）
- 支持加密（可后续）

### 6.2 数据表建议（简化版）

- `articles`：id、title、category、created_at、updated_at、llm_version、summary_json
- `keywords`：id、article_id、keyword
- `sources`：id、article_id、type、meta_json、content_text、file_path
- `source_chunks`（可选）：用于 evidence 引用与检索

### 6.3 搜索

- SQLite FTS5（全文检索：标题、摘要要点、源文本、OCR 文本）
- 关键词 tags 走普通索引

---

## 7. 导入导出设计

### 导出格式

1. **JSON（完整可恢复）**
   - 包含：articles、sources、keywords、mindmap、outline、meta
   - 图片：可打包 ZIP 附件目录

2. **Markdown（便于阅读与迁移）**
   - 标题
   - Keywords
   - Outline（列表）
   - Mindmap（可用 Mermaid mindmap 或缩进树）
   - Source（引用链接/原文/图片链接）

### 导入

- 支持导入 App 自己导出的 JSON/ZIP
- 处理策略：ID 冲突自动重映射；图片按哈希去重

## 8. 系统架构与模块划分（便于写代码）

### 客户端模块

- `IngestionService`：链接抓取、文本清洗、图片 OCR/caption
- `LLMService`：prompt 管理、JSON schema 校验、重试
- `ArticleComposer`：将 AI 输出 + sources 合并成 Article
- `Storage`：DB + 文件
- `Search`：FTS 索引更新
- `ImportExport`：JSON/MD/ZIP

### 服务端（可选）

- 若模型调用放云端：
  - `/analyze`：输入 chunks → 返回结构化 JSON
  - `/upload`：图片上传
  - 鉴权、限流、日志

> MVP 可先客户端直连模型 API（注意密钥安全），正式产品建议走服务端。

---

## 9. Prompt 设计（核心约束）

- 明确角色：信息整理助手
- 明确输出：严格 JSON，不要多余文本
- 明确风格：标题清晰、要点短句、关键词可检索
- 明确语言：跟随用户输入语言（默认中文）

**失败重试策略**

- JSON 解析失败 → 让模型“只修复 JSON”
- 字段缺失 → 让模型补齐缺失字段
- 太长 → 压缩 points 长度/数量

---

## 10. 边界与异常处理

- 链接抓取失败：提示原因（403/需要登录/超时），允许用户粘贴正文替代
- 图片过大：压缩后再传/再 OCR
- 模型超时：保存草稿 sources，稍后可继续生成
- 隐私：提示“源内容会用于生成总结”，若走云端需明确上传范围

---

## 11. 里程碑（开发拆分）

**MVP 1（最小可用）**
- 文本输入 → LLM → 文章生成
- 文章列表/详情
- 本地存储 + 搜索（标题/关键词）

**MVP 2**
- 链接抓取正文
- 图片上传 + caption（可先不 OCR）
- 导出 JSON/Markdown

**MVP 3**
- 思维导图可视化
- OCR + 证据引用（可选）
- 导入 ZIP/JSON
